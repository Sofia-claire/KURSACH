# Smart Excel (Умный Эксель)

## Введение
Кроссплатформенное десктопное приложение для автоматизации консолидации, очистки и нечёткого сопоставления табличных данных из различных отчётных форм Excel. 

Проект разработан в рамках курсового проектирования с упором на автоматизацию ETL-процессов, контейнеризацию и обеспечение качества через CI/CD пайплайны.

## Основной функционал
* **Нечёткое сопоставление строк:** Интегрирован алгоритм на основе расстояния Левенштейна для автоматического связывания записей с опечатками, разным регистром или инверсией слов.
* **ETL и Валидация (Pandas):** Автоматическая очистка входящих файлов от дубликатов, обработка пустых ячеек (NaN) и приведение типов к единому стандарту.
* **Локальное хранилище (SQLite):** Быстрая реляционная база данных для персистентного хранения сопоставленных данных и логов ошибок с контролем уникальности записей.
* **Современный GUI:** Интерфейс выполнен на библиотеке `CustomTkinter` с поддержкой темного/светлого режимов адаптивного дизайна.
* **Автоматическое тестирование:** Полное покрытие критических узлов (алгоритм Левенштейна, парсер Pandas, транзакции базы данных) юнит-тестами.

## Архитектура системы

Приложение спроектировано по модульному принципу с четким разделением зон ответственности (близко к архитектурному паттерну MVC/MVVM), что обеспечивает независимость бизнес-логики от графического интерфейса:

1. **Модуль представления (GUI):** Построен на базе `CustomTkinter`. Отвечает исключительно за отображение окон, таблиц, прогресс-баров и кастомизацию интерфейса. Не содержит внутри себя расчетов.
2. **Модуль бизнес-логики (Core Engine):** Сердце приложения. Включает в себя алгоритм нечёткого сравнения строк (расстояние Левенштейна) и математические веса для сопоставления текстовых токенов.
3. **Модуль обработки данных (ETL/Pandas Layer):** Отвечает за чтение Excel-файлов, их парсинг, первичную валидацию, очистку от дубликатов и нормализацию текстовых полей перед сопоставлением.
4. **Модуль персистентности (Data Access Layer / SQLite):** Управляет локальной базой данных, отвечает за создание таблиц, индексацию, безопасную запись очищенных данных через SQL-транзакции и логирование коллизий.

## Способ авторизации

Поскольку приложение является десктопным локальным инструментом аналитика (Desktop On-Premise), в нем реализована **локальная ролевая авторизация** для защиты персональных и корпоративных данных:

* **Механизм:** При старте приложения вызывается легковесное окно авторизации. Проверка учетных данных происходит путем сопоставления введенного логина и хэшированного пароля с записями в системной таблице пользователей внутри SQLite.
* **Безопасность:** Пароли не хранятся в открытом виде — применяется хэширование (с использованием соли) средствами стандартной библиотеки `hashlib`, что предотвращает компрометацию данных при прямом копировании файла БД.
* **Сессии:** Авторизация действует в рамках одного запущенного процесса приложения.

## Основные сценарии работы (Use Cases)

Приложение поддерживает три ключевых пользовательских сценария:

### Сценарий 1: Импорт и автоматическая очистка данных
1. Пользователь загружает исходный «грязный» файл Excel через диалоговое окно GUI.
2. Система запускает ETL-пайплайн: Pandas считывает структуру, удаляет дублирующиеся строки, заполняет или отсекает пустые ячейки (NaN), нормализует регистр.
3. Очищенный массив временно кэшируется в оперативной памяти и выводится на экран для предпросмотра.

### Сценарий 2: Нечёткое сопоставление и консолидация
1. Пользователь выбирает эталонную таблицу (базу) и целевую таблицу для сравнения.
2. Система запускает посимвольный и пословный анализ строк по алгоритму Левенштейна.
3. Строки со сходством выше установленного порога (например, 85%) автоматически объединяются. 
4. Строки с критическими расхождениями (коллизии) маркируются и отправляются в специальный лог-отчет для ручной проверки аналитиком.

### Сценарий 3: Экспорт и синхронизация с БД
1. После подтверждения сопоставления пользователем, консолидированные данные пакуются в SQL-пакет.
2. Происходит транзакционная запись в локальную базу данных SQLite с проверкой ограничений уникальности.
3. Пользователь генерирует финальный, идеально чистый отчет в формате `.xlsx` для последующей сдачи руководству.

## Требования к системе
* **Python:** Версия 3.10 или выше.
* **Зависимости:** Полный список библиотек указан в файле `requirements.txt` (включая `pandas`, `customtkinter`, `pytest`).

## Варианты запуска проекта

Вы можете запустить проект тремя способами: как локальный скрипт, через Docker-контейнер или скомпилированный бинарный файл.

### Вариант 1: Локальное виртуальное окружение (Разработка)

1. Создайте и активируйте виртуальное окружение:
bash
   python -m venv .venv
   # Для Windows:
   .venv\Scripts\activate
   # Для Linux/MacOS:
   source .venv/bin/activate
 2. Установите зависимости:
bash
   pip install -r requirements.txt
 3. Запустите приложение:
bash
   python main.py### Вариант 2: Запуск в Docker-контейнере
Проект полностью контейнеризирован, что исключает проблемы с несовместимостью окружения.
 1. Сборка и запуск контейнера:
bash
   docker compose up --build### Вариант 3: Готовый исполняемый файл (.exe)
Для конечных пользователей в каталоге dist/ доступен скомпилированный установщик, не требующий наличия Python на компьютере.
*(Инструкция по пересборке .exe через PyInstaller находится в документации разработчика).*
## Автоматическое тестирование (QA)
В проекте реализовано модульное тестирование с использованием фреймворка pytest. Тесты проверяют три критических бизнес-сценария на искусственном «грязном» датасете:
 1. Корректность работы алгоритма нечёткого поиска при наличии ошибок в строках.
 2. Стойкость парсера Pandas к пустым ячейкам и дубликатам.
 3. Целостность транзакций в SQLite.
### Запуск тестов локально:
bash
python -m pytest -v
### Запуск тестов с генерацией отчета о покрытии кода (Code Coverage):
bash
python -m pytest --cov-report html:cov_html --cov=.
Результаты покрытия будут сохранены в папку ./cov_html.
