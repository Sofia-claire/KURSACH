# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Разработка кроссплатформенного приложения «Умный Эксель» для автоматизации консолидации и нечёткого сопоставления табличных данных
### Введение
Настоящее техническое задание (далее — ТЗ) определяет требования к разработке десктопного программного обеспечения «Умный Эксель». Система предназначена для автоматизации процессов извлечения (Extract), трансформации (Transform) и загрузки (Load) данных (ETL) из разрозненных отчётов формата Excel, очистки их от аномалий и дубликатов, а также проведения нечёткого сопоставления текстовых полей со сложной морфологией.
### Основание для разработки
Разработка системы выполняется в рамках курсового проектирования по дисциплине, связанной с разработкой программного обеспечения на языке Python и автоматизацией корпоративных баз данных.
### Назначение системы
Система предназначена для минимизации ручного труда аналитиков и исключения человеческого фактора при сведении «грязных» табличных отчётов. Программа обеспечивает быстрое нахождение логических связей между записями, содержащими опечатки, сокращения или инверсию слов, с последующим сохранением эталонного результата в реляционную базу данных.
### Требования к системе
#### 1. Функциональные требования
 * Управление пользователями и локальная авторизация:
   * Блокировка интерфейса до момента успешного прохождения авторизации.
   * Проверка учётных данных (Логин/Пароль) по локальной таблице пользователей.
   * Обеспечение криптографической безопасности: хэширование паролей с использованием соли средствами библиотеки hashlib (алгоритм SHA-256). Хранение паролей в открытом виде запрещено.
 * Модуль импорта и ETL-обработки (Pandas Layer):
   * Загрузка файлов форматов .xlsx и .xls через стандартный проводник операционной системы.
   * Автоматическое сканирование структуры таблиц, удаление дубликатов строк.
   * Обработка пустых или некорректных значений (NaN, Null), приведение текстовых полей к единому регистру и удаление лишних пробелов.
 * Интеллектуальный модуль нечёткого сравнения (Core Engine):
   * Посимвольный анализ строк на основе расчёта расстояния Левенштейна.
   * Возможность настройки гибкого порога схожести (например, от 0% до 100%) через ползунок в интерфейсе.
   * Автоматическая группировка сопоставленных записей.
   * Маркировка критических коллизий (строк с низким коэффициентом совпадения) для их последующего ручного разбора.
 * Модуль хранения данных (SQLite Layer):
   * Транзакционная запись очищенных и консолидированных данных в локальную реляционную БД SQLite.
   * Контроль целостности данных и ограничений уникальности (PRIMARY KEY, UNIQUE).
   * Логирование ошибок сопоставления в системный журнал внутри БД.
 * Пользовательский интерфейс (GUI):
   * Реализация на базе современного фреймворка CustomTkinter.
   * Поддержка динамического переключения тем оформления (Тёмная / Светлая).
   * Отображение таблиц данных (компонент предпросмотра) и прогресс-баров для отображения статуса тяжелых вычислительных процессов.
 * Модуль экспорта и отчетности:
   * Выгрузка финальной консолидированной таблицы обратно в формат .xlsx.
   * Сохранение структуры данных и автоматическое форматирование результирующего документа для удобства чтения.
#### 2. Нефункциональные требования
 * Технологический стек:
   * Язык программирования: Python версии 3.10+
   * * Графический интерфейс: CustomTkinter / Tkinter
   * Анализ данных: Pandas, OpenPyXL
   * База данных: SQLite 3
   * Тестирование: Пакет pytest (с плагином pytest-cov для оценки покрытия)
   * Контейнеризация и DevOps: Docker, Docker Compose, CI/CD Пайплайн (GitHub Actions / GitLab CI)
 * Производительность и отказоустойчивость:
   * Время обработки и очистки стандартного датасета (до 5000 строк) библиотекой Pandas не должно превышать 3 секунд.
   * Приложение должно стабильно работать локально (On-Premise) без необходимости постоянного подключения к сети Интернет.
 * Надёжность:
   * Защита от критических падений приложения (Crash-resistance) при загрузке файлов некорректной структуры — обработка исключений через блоки try-except.
   * Вывод понятных пользователю валидационных сообщений при ошибках ввода или пустых полях.
### Состав и содержание работ по разработке
 1. Проектирование: Разработка схемы реляционной БД SQLite, описание математической модели весов алгоритма Левенштейна.
 2. Разработка бэкенда: Реализация парсеров Pandas, настройка транзакций SQLite, написание ядра нечёткого поиска.
 3. Разработка GUI: Верстка окон авторизации, главного экрана, табличных виджетов на CustomTkinter.
 4. Покрытие тестами: Написание юнит-тестов (pytest) для проверки корректности хэширования, очистки данных и расчёта расстояний между строками.
 5. Контейнеризация: Написание Dockerfile и docker-compose.yml для изолированного запуска среды разработки и тестов.
### Порядок контроля и приёмки
Приемка работы осуществляется на основании демонстрации работоспособности системы:
 * Успешное прохождение всех автоматических юнит-тестов (метрика покрытия кода тестами должна быть не менее 75%).
 * Корректная сборка проекта внутри Docker-контейнера.
 * Демонстрация полного цикла: Авторизация \rightarrow Импорт грязного файла \rightarrow Нечёткое сопоставление строк с регулировкой порога \rightarrow Экспорт чистого файла и запись в SQLite.
